# AI Prompt 与问题解决记录

## 用过的需求提示

- 「先阅读这个飞书，本阶段不写代码，只做需求理解……你要按轮次提问，每轮只问当前前置条件已经明确的问题。」
- 「对话、摘要和待办都按 session 隔离。切回旧会话时，Agent 只从该会话恢复和召回。」
- 「将待办变更与对应成功记录一起提交，恢复对话时从最后一轮完整问答继续。」
- 「新一批工具只有在整批能执行、且还剩一次模型请求可回传结果时才开始。」
- 「无密钥验收走自动化测试，交互演示走真实模型。」

这些提示先用于澄清决策，随后转为实现约束和测试场景。模型协议查阅了 [DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)，SQLite 的提交与回滚查阅了 [Python 3.12 文档](https://docs.python.org/3.12/library/sqlite3.html)。

## 问题与验证

| 问题 | 处理 | 已验证的证据 |
|---|---|---|
| 工具已写入，CLI 在最终答复前退出 | 写入和成功记录一起提交。启动时标记未结束运行，进入会话时提示已保存变更。 | 测试在工具结果已交给本机 HTTP 替身后终止子进程，再重启核对提示与 SQLite 内容。 |
| 同一批工具同时有读取和写入 | 按模型返回顺序执行，结果以调用 ID 对应回传。 | 测试在一次响应内新增后查询，验证读取包含刚写入的待办。 |
| 工具记录失败可能留下孤立的变更 | 写入和记录由同一个事务管理，记录失败时回滚。 | 注入记录失败，再打开 SQLite 验证待办和成功记录均未保存。 |
| 存量对话过长，新请求还要继续追问 | 对旧轮次滚动摘要，保留近期原文及关键工具结果。 | 调低预算触发摘要，验证摘要放置、早期事实、原始历史和请求次数。 |
| 执行到上限可能只做半批 | 工具批次开始前检查整批预算和剩余模型请求次数。 | 用混有参数失败的批次验证计数和已提交变更。 |
| Windows 保存了密钥，已打开的 IDE 进程尚未继承 | 连接 DeepSeek 时优先使用进程环境，缺失时读取 Windows 已保存的 DeepSeek 变量。 | 在子进程中移除密钥环境变量，使用 Windows 系统变量完成真实工具调用。 |
